# Design — strict 2CBH gold and generation-aware public interface

## Existing gaps to close

At baseline 07716d49, native v2 works on a very large real corpus but is not integrated or strict everywhere. In crates/cbvault/src/pgn/mod.rs, write_game_v2 ignores annotation validation/indexing failures and writes Bare moves. In crates/cbvault-format/src/twocbh/annotations.rs, iterator unknown types stop with None. In bridge/mod.rs and pgn/parallel.rs some .ok() calls hide absent or corrupt annotation frames. In bridge/walk.rs, GameBuf::view deliberately delivers None for v2 annotations. In bridge/search.rs, scan invokes a classic-only entity accessor, and position search uses classic record parsing. In bridge/convert.rs, convert_parallel dispatches v2 to for_each_game sequential. generation_of prefers classic siblings even on explicit v2 member paths. gold_pgn.rs is a manual, non-failing diagnostic with restricted tags and string-pattern SAN exceptions.

## Implementation contracts

**Fail closed:** A v2 game with an annotation offset must return a typed failure if the .2cba file or referenced record is absent, invalid or unknown, rather than become an unannotated success. Unknown type code and offset shall be available in the error. The v2 writer must use the same propagate-error contract as classic. Preserve native-only valid payload via typed borrowed access; if unknown length prevents safe skip, stop with a typed error. Never silently truncate a valid annotation iterator or ignore errors in a requested GameSink annotation view. Instrument error/failure counters in every path.

**Generation-aware operations:** Database::open(path) must privilege an explicit .2cbh/.2cbg/.2cba/.2lid extension even when classic shares a basename; classic explicit members likewise. Ambiguous extensionless stems must not guess. No v2-reachable public function may panic due to classic-only assumptions. Implement version-aware entity/name lookup, tag scan, position search with gigachess and start FEN, early-stop and cancellation, full GameSink annotations and true parallel ordered conversion. Header kinds, deleted/text/analysis slots and record IDs retain semantics. No extra chess core.

**Parallel contract:** Across 1/2/4 and N workers on the same synthetic source, emitted game IDs, moves2, Polyglot keys, annotations, failure IDs, cancellation prefix and ordered output shall be byte/field equivalent. Use bounded in-flight chunks and reusable per-worker storage; meet existing zero-alloc hot-path constraints and measure actual workload after the private gold run. Do not implement parallelism merely for PGN while sink conversion stays serial.

## Byte-accurate gold design

Implement an executable strict local comparator, not just a report generator. Require explicit private source stem and matching ChessBase PGN; record SHA-256 and bytes for source companions (before/after), ChessBase PGN and cbvault PGN; report first raw differing byte. Implement streaming full PGN tokenization: exact escaped tag parsing and all tags, line endings/whitespace policy, braces/comments and semicolon comments spanning physical lines, RAV, NAG, result, null, SAN, Unicode/charset, exact node attachment. Map every source 1-based eligible ID to ChessBase export order; distinguish deleted/text/analysis slots, duplicate/extra/missing/reordered/truncated games. Never assume an ordinal mapping without validation.

**Two distinct verdicts:** raw byte equality; strict byte equality after ONLY explicitly approved transformations. Formatting-only transforms (CRLF vs LF, whitespace between PGN tokens, tag ordering if approved) must not alter literal comments/tags. Semantic or ChessBase-specific transformations require a named, contextual, proof-backed, per-byte occurrence ledger. Board-verification for SAN must parse both moves and compare legal source move and board; the other same-type candidate must be illegal to justify redundant qualification. ChessBase Z0 maps to -- only for an actual legal null node. PUA/diagram/clock/mojibake conversions must each be exact, evidence-backed and independent, not blanket comment stripping. Every nonapproved differing byte, bad mapping, malformed game, unknown valid annotation or nonzero decode failure exits nonzero; never accept a match rate threshold.

**Synthetic checker contract:** Public CI contains miniature generated input/gold pairs that exercise equal output and intentional formats. Negative cases changed one tag byte, comment byte/Unicode, NAG, result, RAV shape, SAN, missing/extra/reordered/duplicated game, fake null and a second LEGAL same-type move must fail. Check parser boundary splitting, CRLF/UTF-8, quoted tags, multiline comments and full 2CBH annotation type errors. No private licensed games in tests or CI.

## Compatibility, scope and security

Keep classic .cbh/.cbv/.cbz byte-output floors and one gigachess core; generated native v2 fixtures and fuzz tests only on GitHub. Do not copy later AGPL oschess or unlicensed Java; only audited MIT/facts-clean-room evidence. Gold/game details stay local, aggregate safe status only in logs. Real coverage is explicitly **Mega Database 2026 only**; additional private databases are NOT a task prerequisite. Chess960 and rare multimedia/training/quoted structures may be absent and remain real-data unverified; include that limitation in README, release note and final review.

After current agent commits the implementation and five checks pass, next agent runs the private Mega corpus, fixes all real mismatches, produces a classified aggregate proof, and requests review before publishing. See gold-runbook.md.
